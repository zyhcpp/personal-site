# 个人主页（综合博客站）设计文档

- **日期**：2026-06-09
- **状态**：已通过设计评审，待用户最终审阅
- **项目位置**：`D:\projects\personal-site`（D 盘干净的新仓库，与 C 盘用户主目录里那个误创建的 8GB git 仓库无关）

## 1. 目标与背景

搭建一个以技术博客为主、带个人介绍的个人站点，体验对齐 `blog.chencs.online` 这类技术/刷题博客：Markdown 写作、代码高亮、目录导航。要求轻量、零运维、免费部署、加载快、安全。

**明确排除（YAGNI）：**
- 后台管理系统与数据库（最初设想，评审后判定为过度设计）
- 作品集页面、归档页面（用户决定删除）
- 数学公式支持（用户决定不需要，未来可加）
- 单元测试框架（内容站风险由 schema 校验 + 构建验证覆盖）

## 2. 技术选型

**Astro**（静态站点框架）。理由：在"博客阅读体验 + 综合站灵活性 + 零运维部署 + 性能"四个维度最均衡。内置 Markdown/MDX、Shiki 代码高亮、Content Collections 校验，默认零 JS、性能极佳，部署到 Vercel 一键完成。

对比落选：Hugo（非博客页面定制灵活性较弱）、Next.js（对纯内容站偏重，属杀鸡用牛刀）。

**关键依赖/集成：**
- Astro Content Collections（内容管理 + schema 校验）
- Shiki（代码高亮，Astro 内置）
- Pagefind（静态站内搜索，构建时生成索引，纯前端运行）
- RSS、sitemap（Astro 官方集成）
- 明暗主题切换（记忆用户选择）

## 3. 站点结构

### 页面与路由

| 页面 | 路径 | 内容 |
|------|------|------|
| 首页 | `/` | 顶部简短个人介绍（头像 / 名字 / 一句话 / 社交链接）+ 最新几篇文章 |
| 文章列表 | `/blog` | 全部文章（标题、日期、摘要、分类、标签），支持分页 |
| 文章详情 | `/blog/[slug]` | Markdown 正文、代码高亮、目录(TOC)、上/下篇导航、阅读时间、发布日期 |
| 标签总览 | `/tags` | 全部标签列表 |
| 单标签筛选 | `/tags/[tag]` | 该标签下的文章 |
| 分类总览 | `/categories` | 全部分类列表 |
| 单分类筛选 | `/categories/[category]` | 该分类下的文章 |
| 关于 | `/about` | 详细自我介绍、经历、技能 |
| 404 | （自定义） | 友好的未找到页面 |

**导航栏**：文章 · 标签 · 分类 · 关于（外加搜索框）

**标签 vs 分类**：分类是单一大类归属（如「算法」「随笔」），标签是多对多细分（如 `LeetCode`、`动态规划`）。每篇文章可属于一个分类、携带多个标签。

### 目录结构

```
D:\projects\personal-site\
├── src/
│   ├── pages/          # 路由页面（对应上表）
│   ├── layouts/        # 页面布局模板
│   ├── components/     # 复用组件（导航栏、页脚、文章卡片、TOC、搜索框、主题切换…）
│   ├── content/
│   │   └── blog/       # Markdown 文章（写作入口）
│   └── styles/         # 全局样式
├── public/             # 静态资源（图片、favicon）

```

写博客 = 在 `src/content/blog/` 新建一个 `.md` 文件，构建时自动渲染并出现在列表/标签/分类页中。

### 文章 frontmatter 字段

每篇 Markdown 文章头部包含：标题(title)、日期(date)、摘要(description)、分类(category)、标签(tags)。由 Content Collection schema 强制校验。

## 4. 功能清单

**博客阅读体验：**
- Markdown 渲染（标准语法、表格、引用、图片）
- Shiki 代码高亮（多语言、行号）
- 自动目录(TOC)，可点击跳转
- 上一篇 / 下一篇导航
- 阅读时间估算、发布日期

**站点级：**
- 暗色 / 亮色主题切换（记忆选择）
- 响应式（手机 / 平板 / 桌面）
- 站内搜索（Pagefind）
- RSS 订阅、sitemap
- SEO：每页 meta 标签 + Open Graph 分享卡片

**不做：** 数学公式、评论系统、用户登录、数据库（均为未来可选项）

## 5. 视觉样式

简洁、内容优先、留白充足的技术博客风格（对齐参考站）。正文用易读无衬线/系统字体，代码用等宽字体。提供明暗双主题，主色调可定制。

## 6. 数据流

```
写 .md 文章 (src/content/blog/)
        │
        ▼
Astro 构建 (npm run build)
   · 读取并校验 frontmatter（标题/日期/摘要/分类/标签）
   · Markdown → HTML + 代码高亮 + TOC
   · 生成文章页、列表页、标签页、分类页、首页、关于页
   · Pagefind 扫描产物生成搜索索引
   · 生成 RSS / sitemap
        │
        ▼
   dist/ 静态文件（纯 HTML/CSS/JS）
        │
        ▼
   部署到 Vercel → 访客访问
```

**核心特性：无运行时后端、无数据库。** 所有页面构建时生成，访客获得纯静态文件——快、便宜、安全。

## 7. 错误处理

静态站的"错误处理"主战场是构建期：

- **内容 schema 校验**：用 Content Collections 给 frontmatter 定义规则（必填字段、日期格式、字段类型）。某篇文章漏写或写错 → 构建直接报错并指出具体文章与字段，坏页面不会发布。
- **构建失败即拦截**：Vercel 流水线中构建失败则不上线，保护线上版本。
- **自定义 404**：友好的未找到页面处理无效链接。

## 8. 部署与托管

- **代码托管**：GitHub 仓库。本地在 `D:\projects\personal-site` 开发，`git push` 推送。
- **部署平台**：Vercel。连接 GitHub 仓库，每次 push 自动构建并部署；免费额度充足、自带全球 CDN、自动 HTTPS。
- **流程**：本地 `npm run dev` 开发预览 → 提交 → push → Vercel 自动上线。

## 9. 测试策略

内容站以"构建即验证"为主，不引入重型单测框架：

1. **内容 schema 校验**：frontmatter 错误在构建期暴露。
2. **构建测试**：`npm run build` 成功产出为核心保障，纳入 Vercel 流水线。
3. **链接检查**（可选）：构建后检查死链。
4. **手动验收清单**：首页、文章渲染、代码高亮、TOC、暗色模式、搜索、标签/分类筛选、RSS、响应式、404 逐项核对。
